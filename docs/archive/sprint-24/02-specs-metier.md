# Spécifications Fonctionnelles : Lot 6 — Sprint 24 (Module « Facturation PDF Officielle & Envoi Automatique »)

## 1. Règles de Gestion (RG) et Cas Limites
| ID RG | ID US Liée | Description de la règle métier | Comportement en cas d'erreur / Cas limite |
|---|---|---|---|
| `RG-01` | `US-LOT6-01` | Le module `FacturationApi` / `FacturationUi` suit le cycle de vie SDK v2 (`/sys-modules`). À l'installation, il crée `mod_facturation_invoices` et `mod_facturation_settings` (compatibles SQLite & MySQL) ainsi que le template d'e-mail dédié `invoice_issued` dans `email_templates` s'il n'existe pas. | À la désinstallation, ses tables `mod_facturation_*` et ses assets publiés sont purgés ; `/factures` et `/api/v1/modules/facturation/*` retournent `404`. |
| `RG-02` | `US-LOT6-01` | Chaque facture officielle reçoit un numéro séquentiel unique par année au format `{prefix}-{YYYY}-{0001}` (défaut `FAC-2026-0001`), un type de source (`cotisation`, `boutique`, `autre`), une référence source optionnelle (`source_id`), les coordonnées du destinataire, le détail JSON des lignes, les remises, le total net et le chemin relatif du fichier PDF dans `storage/private_uploads/invoices/`. | L'émission d'une facture pour une même paire `(source_type, source_id)` non nulle est **idempotente** : si une facture existe déjà pour ce dossier, elle est retournée sans créer de doublon de numéro légal. |
| `RG-03` | `US-LOT6-02` | Le template PDF spécifique est administrable depuis `/factures` (onglet Paramètres Template PDF & E-mail, réservé à `finances.manage` / Superadmin) : `invoice_prefix`, `org_name`, `org_legal_id` (RNA / SIRET), `org_address`, `org_email`, `header_title`, `footer_mentions`. Le PDF généré commence impérativement par `%PDF-1.4`, contient le numéro légal, le destinataire, les lignes, la remise éventuelle, le total net et les mentions légales configurées. | Si un champ obligatoire (destinataire, montant >= 0, au moins 1 ligne) est manquant lors d'une émission manuelle, l'API rejette avec JSend `422`. |
| `RG-04` | `US-LOT6-03` | À chaque émission d'une facture (automatique via `on_registration_validated`, manuelle depuis `/factures`, ou depuis un module tiers via `InvoiceService`), un e-mail est automatiquement envoyé au destinataire via `MailerService` en utilisant le **template d'e-mail dédié `invoice_issued`** (variables `{{recipient_name}}`, `{{invoice_number}}`, `{{total_amount}}`, `{{club_name}}`, `{{source_label}}`) avec le **fichier PDF joint en MIME `application/pdf`**. L'état d'envoi (`email_status`: `sent` / `failed`) est tracé sur la facture et dans `email_logs`. | Si l'envoi SMTP échoue, la facture PDF reste validée et archivée (`email_status = 'failed'`), et le Bureau peut déclencher un renvoi manuel (`POST .../invoices/{id}/send-email`). |
| `RG-05` | `US-LOT6-04` | L'accès aux factures est strictement contrôlé : les gestionnaires (`finances.manage` ou Superadmin) voient toutes les factures, peuvent configurer les templates PDF/e-mail, émettre une facture manuelle et renvoyer un e-mail. Un Adhérent connecté ne voit et ne peut télécharger (`GET .../invoices/{id}/pdf`) que les factures dont il est le payeur (`user_id`) ou dont l'e-mail correspond à son compte. | Tout Adhérent tentant de télécharger une facture d'un autre adhérent, ou de modifier les templates / émettre une facture, reçoit JSend `403`. Un Visiteur non connecté reçoit `401`/`403`. |

## 3. Scénarios de Recette Utilisateur (UAT)
- **Persona 1 (Trésorier / Président — Personnalisation template PDF + e-mail, émission automatique & manuelle, pièce jointe SMTP réelle) :** Le Superadmin active `FacturationApi`. Le Président configure sur `/factures` les mentions légales du template PDF (`RNA W790012345`) et le sujet du template d'e-mail `invoice_issued`, puis émet une facture manuelle (ou valide un dossier d'inscription). Un fichier PDF binaire valide (`%PDF-1.4`) est généré dans `storage/private_uploads/invoices/`, téléchargeable depuis l'UI, et transmis en pièce jointe MIME `application/pdf` sur le transport SMTP.
- **Persona 2 (Adhérent — Cloisonnement strict RGPD/RBAC `403` + Désinstallation propre) :** Un Adhérent accède à `/factures` : il ne voit pas les formulaires d'administration, peut télécharger sa propre facture mais reçoit `403` s'il tente de télécharger la facture d'un tiers ou de modifier les templates. Le Superadmin désinstalle `FacturationApi` : `/factures` et `/api/v1/modules/facturation/*` retournent `404` et les assets sont purgés.
