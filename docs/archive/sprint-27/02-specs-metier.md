# Spécifications Fonctionnelles : Lot 7 — Sprint 27 (QA Intégrale 100 % UI, Audit Vues & Mailpit)

## 1. Règles de Vérification (RG)
| ID RG | ID US Liée | Description de la règle de validation | Critère d'échec / Anomalie à corriger |
|---|---|---|---|
| `RG-01` | `US-LOT7-01` | Toutes les connexions de la suite Sprint 27 passent exclusivement par les formulaires réels `/login` (email + `password123`) et `/sys-admin-xyz` (`superadmin` + `password123`) et la déconnexion par le bouton UI de déconnexion. Zéro appel `POST /api/v1/auth/switch-persona`. | Toute impossibilité de se connecter/déconnecter ou d'exécuter un parcours métier uniquement par clics UI est une anomalie bloquante. |
| `RG-02` | `US-LOT7-02` | Matrice RBAC 8 profils vérifiée sur la Sidebar et les routes directes : **Visiteur** (accueil, `/horaires`, `/register`, `/login`, `/boutique` sans admin ; redirigé sur `/members`, `/stats`, `/cms`), **Adhérent** (`tutorA@mail.com` : profil, `/presences` interdit, `/evenements`, `/factures`, `/boutique` sans admin), **Entraîneur** (`tutorB@mail.com` : `/members` anonymisé, `/stats`, `/presences`, `/evenements`, pas `/registrations`, pas `/roles`), **Rédacteur** (`redacteur@mail.com` : `/cms`, pas `/members`, pas `/stats`), **Secrétaire** (`secretaire@kanso-ya.local` : `/members`, `/cms`, `/stats`, pas `/registrations`, pas `/roles`), **Trésorier** (`tresorier@kanso-ya.local` : `/members`, `/registrations`, `/factures`, `/boutique` avec admin, pas `/cms`, pas `/roles`), **Président** (`president@kanso-ya.local` : tout le métier + `/roles` + `/disciplines` + `/settings`, pas `/sys-console`), **Superadmin** (`/sys-console`, `/sys-branding`, `/sys-smtp`, `/sys-modules`, `/sys-logs`, accès `/cms` bloqué). | Tout menu affiché à tort, manquant, ou toute route métier accessible sans droit est une anomalie RBAC à corriger. |
| `RG-03` | `US-LOT7-03` | La suite Sprint 27 est exécutée sur 7 projets Playwright dédiés (`playwright.sprint27.config.ts`) : Desktop (`chromium`, `firefox`, `webkit`) + Mobile (`Pixel 5`, `Galaxy S9+`, `iPhone 13`, `iPhone 15 Pro`). | Échec sur un moteur (Firefox/WebKit) ou un viewport mobile. |
| `RG-04` | `US-LOT7-04` | Audit de propreté sur toutes les vues à onglets (`/stats`, `/disciplines`, `/sys-smtp`, `/profile`, `/factures`, `/boutique`) : à chaque onglet actif, exactement 1 panneau d'onglet visible (aucun bloc dupliqué ni contenu orphelin hors onglet), zéro `console.error` / `pageerror`, zéro réponse HTTP `>= 400` inattendue, zéro lien interne `a[href]` cassé, et `documentElement.scrollWidth <= window.innerWidth + 2` sur mobile. | Présence de doublons/orphelins, erreurs JS/réseau ou débordement horizontal sur mobile → nettoyage ciblé de la vue concernée. |
| `RG-05` | `US-LOT7-05` | Tests Mailpit réels en 2 temps avec purge `DELETE http://127.0.0.1:8025/api/v1/messages` avant chaque phase/scénario : **(1) Surcharge `.env`** (`SMTP_TRANSPORT=smtp`, `SMTP_HOST=127.0.0.1`, `SMTP_PORT=1025`, `SMTP_ENCRYPTION=none`) vérifiée par envoi réel + lecture API Mailpit ; **(2) Configuration 100 % UI** (sans surcharge `.env`, saisie manuelle dans `/sys-smtp`, sauvegarde, envoi mail de test + flux métier réel ex. mot de passe oublié / facture PDF) vérifiée dans Mailpit (destinataire, sujet, HTML, liens cliquables). | Si la surcharge `.env` n'est pas respectée par `MailerService`, corriger `MailerService::getEffectiveConfig()`. |
